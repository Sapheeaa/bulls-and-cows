# DESIGN.md

## 1. Структуры данных и алгоритмы

**Состояние игры (GameState)**
В приложении используется иммутабельный объект `GameState`. Он содержит настройки (`length`, `base`), сгенерированный секрет (`secret`), массив истории попыток (`history`), текущий статус (`playing` или `won`) и время старта (`startTime`).
При добавлении новой попытки состояние не мутируется, а создается новое через spread-оператор: `state = { ...state, history: [...state.history, newAttempt] }`. Это гарантирует предсказуемость и позволяет легко отслеживать изменения.

**Алгоритм `evaluateGuess`**
Функция сравнивает два массива символов (секрет и попытку). Сначала через `filter` вычисляются «быки» (совпадение символа и индекса). Затем массивы очищаются от быков, и через `filter` и `includes` вычисляются «коровы» (символ есть в секрете, но не на своем месте). Используются только HOF (`filter`, `includes`), без циклов `for`.

**Алгоритм `countPossibleSecrets`**
Вычисляет количество перестановок без повторений: \(P(base, length) = \frac{base!}{(base - length)!}\). Реализован рекурсивно: база рекурсии — `length === 0` возвращает `1`, шаг — `base * countPossibleSecrets(length - 1, base - 1)`. Для оптимизации используется мемоизация (кэш на основе `Map`), чтобы не пересчитывать значения при повторных вызовах (например, при смене настроек).

## 2. Сложность (Big O)

- **`generateSecret`**: \(O(n)\), где \(n\) — длина секрета. На каждой итерации выбирается случайный символ, а массив доступных символов уменьшается. Так как `n` ≤ 6, сложность практически константная.
- **`evaluateGuess`**: \(O(n^2)\), где \(n\) — длина секрета. Поиск быков занимает \(O(n)\), а поиск коров через вложенный `includes` — \(O(n^2)\). Для `n` ≤ 6 это несущественно.
- **`isValidGuess`**: \(O(n)\). Проверка длины \(O(1)\), проверка каждого символа через валидатор \(O(n)\), проверка уникальности через `Set` \(O(n)\).
- **`countPossibleSecrets`**: \(O(n)\) без мемоизации (глубина рекурсии \(n\)), и \(O(1)\) при повторном вызове благодаря кэшу.

## 3. Принципы чистого кода

1. **Single Responsibility (Единственная ответственность)**: Логика игры полностью отделена от интерфейса. Файлы в `src/logic/` содержат только чистые функции, которые ничего не знают о DOM. UI-код находится в `src/ui/main.ts`.
2. **DRY (Don't Repeat Yourself)**: Функция `createDigitValidator` используется в двух местах: в `isValidGuess` для валидации всей попытки и в `main.ts` для фильтрации ввода в реальном времени.
3. **Immutability (Иммутабельность)**: В `main.ts` состояние `state` обновляется только через создание новых объектов (`{ ...state }`). В логике массивов используются `filter` и `map`, которые не мутируют исходные данные.
4. **Naming (Именование)**: Переменные и функции названы так, чтобы отражать их суть (`isValidGuess`, `bulls`, `cows`, `startTime`).
